# 15 — Risk Register

| ID | Risk | Likelihood | Impact | Mitigation | Owner/Status |
|---|---|---|---|---|---|
| R-01 | R1 evidence is thin — the Codex contribution is not visibly documented, so "built with Codex" cannot be demonstrated | **Medium** | **Fatal** — R1 is the compliance route since PD-009 | `19-codex-contribution-log.md` must be filled in by real Codex sessions, per commit, and must be checkable against `git log`. An empty log at submission time is the failure mode | Open |
| R-01b | An entry is written for Codex work that did not happen | Low | **Fatal** — dishonesty on a judged dimension | Standing prohibition 2 in `02-competition-rules.md`; non-Codex agents log to `12-change-log.md` instead | Open |
| R-02 | The rule-based assistant fails on real free-text input and the product feels rigid or hollow | **Medium** | High | The interview asks rather than guesses; out-of-coverage input gets an honest "no template for this" plus search, never a confident wrong answer. Measured against the eval set in `11-evaluation-log.md` before the journey is called done | Open |
| R-03 | The assistant recommends the wrong public authority and the citizen trusts it | Medium | High | Names come only from the captured real list, so a non-existent authority is impossible by construction; reasoning is always shown, alternatives are always offered, the choice is always editable (PD-004) | Open |
| R-04 | A fee, deadline or section number shown to the citizen is wrong | **Low** — all such facts are code constants with citations | High | Owned solely by the rules module, unit-tested, never authored inside template prose (`09-ai-behavior.md` rule 4) | Open |
| R-05 | The prototype is mistaken for an official government service | Low | **High** — rule R13 | Distinct name, no emblem or government mark, permanent disclosure in-product, visibly fake registration numbers | Open |
| R-06 | An API key or secret is committed | **Very low** — no runtime key exists (PD-009) | High | `.gitignore` covers `.env*`; secret scan required before each milestone (master instruction §33) | Mitigated, needs the scan step automated |
| R-07 | Scope creep into a portal clone or an admin console | Medium | High | PD-001, R6, and the out-of-scope list in `04-user-problem.md` | Open |
| R-08 | Time runs out with a half-built journey | Medium | **High** — "Working build" is a judging dimension | Build the journey end-to-end thin first, then deepen. Keep a working demo path at every commit | Open |
| R-09 | Instruction-shaped text in the citizen's description is treated as instruction | **Low** — no model interprets it (PD-009) | Medium | Input is data throughout; the injection cases stay in the eval set so the guarantee is re-checked if a model is ever added | Largely retired by PD-009 |
| R-13 | The product implies a language model is reasoning when none is | Medium | **High** — Honesty is a judged dimension | No fake thinking states or confidence theatre; the product explains its actual method (`09-ai-behavior.md`, rule 4) | Open |
| R-10 | A citizen pastes real personal data (Aadhaar/PAN) into the prototype | Medium | Medium | Detect and warn before it leaves the browser; never persist server-side | Open |
| R-11 | Accessibility claims are asserted but not measured | Medium | Medium | axe gate per route in CI; `18-verification-matrix.md` may not be marked complete without evidence | Open |
| R-14 | The audit's authenticated findings cannot be re-verified cheaply — re-entry needs a human OTP and the token is single-use | High | Medium | Everything observed is written down with reproduction steps and evidence tags before the session ends; `docs/research/rti-online/` is the durable record | Mitigated |
| R-15 | A future capture leaks the owner's real email, mobile or a registration number into the repository | Medium | **High** — privacy | The authenticated form pre-fills real contact details; substitute synthetic values in the DOM before any capture. Rule recorded in `screenshots/README.md` and `08-data-model.md` | Open |
| R-16 | We overstate the improvement over RTI Online and a judge checks | Medium | **High** — Honesty is judged | Every claim traces to an `[O]` finding with reproduction steps; corrections to our own earlier claims are kept visible, not deleted; no "10x easier" language without a measurement | Open |
| R-17 | Our prototype dead-ends a citizen the same way the portal does, on input outside the taxonomy | Medium | High | "No template for this" must still hand the citizen search, an explanation of a good request, and a route onward — never a flat refusal. Tested as J7 | Open |
| R-12 | The captured public-authority list drifts from the live portal | Low | Low | Dated and sourced in the JSON; it is a research snapshot, not a live feed, and the product must never call `*.gov.in` at runtime (R8) | Accepted |
